# Known issues and limitations

Format: `../BLUEPRINTS/KNOWN-ISSUE.md`. Keep facts and assumptions separate.

| ID | Area | Severity | Status | Issue | Evidence / workaround |
|---|---|---|---|---|---|
| KI-001 | server | minor | open | Save-on-change rewrites `world.json` inside the tick; on Docker Desktop bind mounts (and Windows) a save takes ~4-10 ms, producing tick p95 spikes of 7-9 ms | `PERFORMANCE-BASELINES.md`. Options when it matters: background save thread, debounce, named volume instead of a Windows bind mount |
| KI-002 | server metrics | minor | open | `cpu_pct` / `rss_mb` are null for native Windows servers (in-process sampling reads Linux `/proc`) | use `bench server --docker` or `env status` (`docker stats`) |
| KI-003 | networking | major (at scale) | open | Player states are broadcast all-to-all at 15 Hz: traffic ~n² (32 players -> ~460 KB/s out) | interest management / delta compression before large player counts |
| KI-004 | authority | major (for public servers) | accepted | Movement is client-predicted; the server validates speed and bounds but not collisions, so a modified client can pass through obstacles at legal speed | ADR-0003; server-side simulation is a future movement-room milestone |
| KI-005 | client | cosmetic | open | ~150 ms hitch on the frame the world is built after joining | build the world over several frames or behind a loading screen |
| KI-006 | server (native) | minor | observed once | One 37 ms tick in a native Windows benchmark, during a save (suspected antivirus/file system stall; not seen in Docker) | re-measure if native servers become important |
| KI-007 | containers | minor | mitigated | The Godot editor binary logs `Unable to load fontconfig` during headless import in minimal images | `libfontconfig1` installed in the build stage; the runtime image needs nothing extra (zero engine errors at runtime) |
| KI-008 | tests | minor | accepted | Bots move in straight lines without collision; they exercise the protocol, not navigation | fine for current tests |
| KI-009 | client | minor | open | Pick-up targeting is a view cone + distance check, without line of sight | add a physics ray when obstacles matter |
| KI-010 | determinism | info | resolved | Movement golden trajectory (generated on Windows) is bit-exact at float32 on Linux too | verified in the tools container (`room test movement`, Godot 4.7.2 Linux build) |
| KI-011 | tooling | minor | open | Native server CPU/RSS, Linux clients and cross-machine networking are not covered by automated tests | see `DOCUMENTATION/TESTING.md` "Not automated yet" |
| KI-012 | security | info | accepted | Unauthenticated identities, unencrypted ENet, editor binary in the image | `PROTOCOLS/SECURITY.md` unresolved risks |
| KI-013 | movement lab | minor | open | The explicit-Euler movement core remains step-rate dependent between 60 and 120 Hz (at the new 6 m/s default: stop distance 10.0 %, stop time 5.3 %, jump apex 3.0 %) | Original measurements in `DOCUMENTATION/MOVEMENT-LAB-AUDIT.md` section 6; remeasured defaults in `DOCUMENTATION/MOVEMENT-LAB-2.md`; guarded by `test_baseline_behavior.gd`, not fixed |
| KI-014 | movement lab | minor | open | The sandbox's live-tuning hardware checkpoint (task 0003 phase 4) was never confirmed by the user | `TASKS/0003-midi-movement-lab.md`, `TASKS/0004-movement-lab-2.md` open items |
| KI-015 | movement lab legacy | minor | preserved baseline | Legacy generated gait and circling rebake fix remain selectable; Playground now defaults to authored Quaternius clips. Legacy landing uses the fallback. No legacy turn gait, terrain IK or step width | `DOCUMENTATION/MOVEMENT-LAB-2.md`; authored replacement in `DOCUMENTATION/MOVEMENT-LAB-3.md` |
| KI-016 | movement lab | info | accepted | `velocity_match` below 1 intentionally mismatches ankle speed at lift-off/landing; reference defaults now use 1. The stronger reference poses increase some joint accelerations: maximum knee acceleration 787 rad/cycle-squared at 1.6 m/s on the original rig, versus 618 before this revision. Very low edited clearance can engage the sole safety floor | `tools/gait_smoothness.gd`; reference fit is not a claim of lower acceleration everywhere |
| KI-017 | movement lab | info | open | The reference-led walk remains an approximate 2D-to-3D fit; Contact/Down are less exact than Passing/Up. Automated tests verify landmarks, bone ratios, camera/drag controls and contact, not visual acceptance or suitability for other movement modes | task 0004 checkpoints; review the four visible pose buttons with the user |
| KI-018 | movement lab | info | open | Running is a procedural heel-strike prototype, not measured sprint technique or ballistic physics. The longer 7 m/s profile has 2.20 m steps and powered takeoff; support-only reach lowering is 16 mm through 7 m/s and 43 mm at 8 m/s. Airborne feet recover within reach. The 12 m/s sprint uses the same profile at faster cadence with a 2.4 m step cap. Style still needs user review; rig, foot roll and requested hip height remain shared with walking | `DOCUMENTATION/MOVEMENT-LAB-2.md` running prototype; model checks through 15 m/s and real-skeleton checks through 12 m/s, not all extreme tuning combinations |
| KI-019 | movement lab 3.0 | visual checkpoint | open | Authored running is implemented but not user-approved. Near-floor corner slip remains high at low speed and 12 m/s; the diagnostic includes rolling/swing corners and is not an acceptance pass. Flat-floor clearance IK is not world-space planting or terrain IK. Original CC0 source performance is preserved rather than adding more procedural tuning | `DOCUMENTATION/MOVEMENT-LAB-3.md`: native capture metrics, identical-physics A/B, 479 tests; review in side view and with the physical MIDI controller |
